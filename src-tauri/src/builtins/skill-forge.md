# 技能创建器

教你怎么给 aglab 写一份能被模型真正用起来的技能。

## 技能是什么

一份 `SKILL.md` 操作清单。系统提示里只注入清单（名字 + 描述，60 条上限），模型判断当前请求匹配某个技能的描述后，自己调 load_skill 取回正文照着做。所以一份技能的成败几乎全在 **description** 上——它是模型决定取不取的唯一依据。

## 目录与文件

个人技能目录在「设置 → 扩展 → 技能」页顶显示。布局：

```
<技能目录>/
  写日报/
    SKILL.md
  排查构建/
    SKILL.md
```

每个技能一个子目录，文件必须叫 `SKILL.md`。技能也可以放进插件的 `skills/` 里（键会带上插件名前缀）。

## frontmatter

```markdown
---
name: 写日报
description: 用户要写/补工作日报、周报，或给你素材让你汇总成日报时使用
allowed-tools: read_file, search_text, list_files
---

# 写日报

（正文）
```

- **name**（可选）：缺省用目录名。
- **description**（最重要）：写「什么场景下用」，不要写「这是一个日报技能」。模型按它匹配请求。
- **allowed-tools**（可选）：逗号分隔的工具名白名单。这是真闸门——技能被取用后，那一轮只有这些工具可用。留空 = 不额外限制（权限档位照常管）。

## 正文怎么写

- 面向执行：步骤化、命令可复制、判断条件写清楚。模型取回后是照着做的，不是读完参考的。
- 文件路径一律写绝对路径，或写清「相对技能目录」的基准——提示词里已说明相对路径相对 SKILL.md 所在目录解析，但传给文件类工具时要用绝对路径。
- 不要堆背景知识：正文是操作清单，不是文档。长了取用成本就高。
- 需要随素材变的中间产物（草稿、中间文件）写在技能目录里，路径引用自己目录。

## 生效与验证

1. 保存文件，到「设置 → 扩展 → 技能」点刷新。
2. 列表里找到它：看字符数与预览是否是你要的正文（frontmatter 不算正文）。
3. 让模型实际用一次；没取用就回头改 description。
4. 逐条开关在技能页；关掉的技能不进清单，load_skill 也会报「已关闭」。

## 常见错误

- 文件名不是 SKILL.md（如 readme.md）→ 不被扫描。
- SKILL.md 直接放在技能根目录（没有子目录层）→ 不被扫描。
- frontmatter 没闭合（缺第二个 `---`）→ 整份按正文处理，描述退回正文第一段。
- description 写成口号（「高效日报助手！」）→ 模型匹配不上场景。
