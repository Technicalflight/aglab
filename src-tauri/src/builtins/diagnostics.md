# 故障诊断

按症状排查。先读错误原话——aglab 的报错写的是原因，不是行号。

## 发送消息报错

- **连接不上 / 超时**：检查端点档案的根地址拼写（要不要带 /v1 各家不同）；挂了代理的话先在代理页「测试」那条代理；aglab 不读系统代理环境变量，没配就是直连。
- **HTTP 401 / 403**：密钥问题。密钥存 Windows 凭据管理器，档案记的是 service/user 两项；换过密钥就去端点档案里重新保存一次。
- **HTTP 404 / 「线协议」类报错**：中转站常常只开 `/chat/completions` 或 `/responses` 其中一条，把端点档案的线协议换成另一档再试；anthropic 线的根地址带不带 /v1 都接。
- **「池成员指向的档案已经不存在了」**：去模型池把那个成员移除或换成别的档案。
- **「冷却中」**：池子里那位连续失败 3 次进了冷却（30 秒起步逐次翻倍），失败原因去用量页「最近请求」看；等冷却结束自动归队，或手动指定别的成员。

## 「路由 / 池子怎么没生效」

生效档位是一条链：**点名（子智能体、编排、任务点名了模型或端点）> 模型池 > 模型路由表 > 设置直连**。点名了就不经池子与路由；池子接管了（auto/pinned/decision 挑出成员）也不经路由表。路由表只在「跟着设置走」的那一档查；查改写后的实际去向，看用量页记的实际模型名。

## 技能没被用上

- 技能是否被关：技能页与插件详情里都有逐条开关；扩展级开关在插件页「出厂扩展」与插件本体上。
- 清单上限 60 条：超出部分不进系统提示，会注明「另有 N 个技能未列出」。关掉不常用的。
- 描述写得模型认不出场景：description 是模型决定取不取的唯一依据，改成「什么场景下用」的具体句子。
- 直接验证：让模型「load_skill 技能名」取正文，取不到就是键名或开关问题。

## MCP 连不上 / 工具没出现

- 独立配置的服务看命令是否可执行（npx 需要 Node 在 PATH 里）；连接状态在插件页 MCP 区。
- MCP 工具一律按高风险处理，逐项确认与自动放行两档下都会先问；被拒过的工具不会自己再跑。
- 被单独关闭的 MCP 工具（disabled_mcp_tools）不声明给模型。
- 插件自带的服务只能停整个插件，不能单独删。

## 钩子没跑

- 没逐条确认过内容的钩子不执行（runs = false）：插件详情里逐条「信任」。
- 确认后脚本内容改了一个字节：那份确认自动作废，要重新确认。
- 被单独停用的钩子（disabled_hooks）不跑。
- prompt 型处理器暂不支持：它进了 hook_notes，不会静默消失。

## 插件不出现

- 目录层级：`插件目录/<任意目录名>/.claude-plugin/plugin.json`（manifest 可缺，缺了用目录名当插件名），技能在 `skills/<技能目录>/SKILL.md`。
- .mcp.json 不是合法 JSON 会被跳过并有提示。
- 放好后点插件页右上角刷新。

## 出口被拦

- 「出口被拦下：xxx 不在网络出口的域名名单里」：出口名单收紧时（名单非空），模型请求、模型清单、outbound webhook 只能去名单内的域。放行它：设置 → 权限 → 出口域名名单；名单清空 = 不收紧。
- 内网地址（localhost、私有与保留 IP）两道闸恒在，名单放不开。

## 用量对不上

用量按「实际发出的模型名」记账：路由改写、池子成员都会改变实际模型名；缓存命中的请求费用按端点价表的缓存价算。对账先看最近请求的实际模型列。
